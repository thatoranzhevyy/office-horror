# Деплой на Render

Проект разворачивается одним **Web Service**: Node.js-сервер раздаёт собранный сайт и принимает WebSocket-подключения по `/ws`. Отдельный frontend-хостинг и `VITE_WS_URL` не нужны.

## Через Blueprint

1. Загрузите проект в GitHub или GitLab вместе с `render.yaml`.
2. В Render выберите **New → Blueprint** и подключите репозиторий.
3. Подтвердите создание сервиса `office-horror` из Blueprint.
4. После завершения деплоя откройте выданный Render URL. Проверка сервера доступна по адресу `/health`.

Blueprint задаёт Node.js `22.12.0`, установку зависимостей и сборку (`npm ci && npm run build`), запуск (`npm start`), проверку `/health` и размер команд `TEAM_SIZE=2` на каждую команду.

## Создание сервиса вручную

Если создаёте сервис из панели Render, укажите:

```text
New → Web Service
Runtime: Node
Build Command: npm ci && npm run build
Start Command: npm start
Health Check Path: /health
Node version: 22.12.0
```

Добавьте переменную окружения `TEAM_SIZE=2`, если хотите изменить стандартный размер команд. Переменную `PORT` вручную не задавайте: Render передаёт её приложению автоматически.

## WebSocket

Клиент сам подключается к `wss://<домен-render>/ws`, когда страница открыта по HTTPS. Сервер принимает обычный HTTP и WebSocket на одном порту, который получает из `PORT`.

Render Free может приостанавливать сервис после периода бездействия. При новом открытии сайта или WebSocket-подключении сервис запускается снова, поэтому первый вход после простоя может занять время. Во время перезапуска или деплоя активные соединения могут оборваться; игрокам потребуется переподключиться.
